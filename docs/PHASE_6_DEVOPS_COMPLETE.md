## Infrastructure Configuration

### Cloudflare Workers Configuration

**Project Structure:**
```
myschoolweb/
├── wrangler.toml                      # Cloudflare Workers config
├── next.config.js                     # Next.js config (edge-compatible)
├── package.json                       # Build and deploy scripts
├── .open-next/                        # Generated by OpenNext.js (ignored)
│   └── worker.js                      # Main Worker entry point
├── CLOUDFLARE_WORKERS_SETUP_GUIDE.md  # Setup documentation
└── verify-phase6-devops.js            # Verification script
```

### Environment Configuration

**Three Environments:**

1. **Development (default):**
   - Project name: `myschoolweb-dev`
   - Workers URL: `myschoolweb-dev.{subdomain}.workers.dev`
   - Use case: Local testing, development verification

2. **Staging:**
   - Project name: `myschoolweb-staging`
   - Workers URL: `myschoolweb-staging.{subdomain}.workers.dev`
   - Use case: In-house testing, QA validation

3. **Production:**
   - Project name: `myschoolweb-prod`
   - Workers URL: `myschoolweb-prod.{subdomain}.workers.dev` or custom domain
   - Use case: Production deployment (after staging validation)

### Environment Variables

**Public Variables (in wrangler.toml):**
- `NEXT_PUBLIC_SUPABASE_URL`: Supabase project URL
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`: Supabase anonymous key (public)
- `NODE_ENV`: Environment name (production, staging)

**Secrets (via wrangler secret put):**
- `SUPABASE_SERVICE_ROLE_KEY`: Supabase service role key (server-side only)
- `SESSION_SECRET`: JWT signing secret for session tokens

### Build Configuration

**Build Process:**
1. `npm run build` - Next.js production build → `.next/` directory
2. `open-next build --target cloudflare` - Convert to Worker → `.open-next/` directory
3. `wrangler deploy` - Upload Worker to Cloudflare

**Build Output:**
- `.open-next/worker.js` - Main Worker entry point
- Static assets handled by Cloudflare Pages or R2

**Expected Bundle Size:** ~3-5 MB (requires paid plan)
